# 004: Design

## Approach

The site is a thin layer over files that already exist. `docs/` is the MkDocs source directory, so `docs/method.md` is a page without being moved. Pages that would otherwise duplicate repository content are generated during the build by a MkDocs hook, a plain Python file the build calls, from the skills, the templates and the validator's rule list. Authored pages are few and short: home, what and why, six tutorial steps, two entry pages, agents, the example's story.

Two workflows: one deploys the site on push to main, one runs the validator, the test suite and a strict build on pull requests. The test suite grows a file for the site: word counts, UK spelling, configuration, and the hook's output, none of which needs MkDocs installed.

## Decisions

### Decision: MkDocs Material with a build hook, no extra plugins
- Chosen: Material theme, built-in Mermaid and content tabs, and one hook file that generates the skills, templates and validator pages.
- Alternatives considered: the snippets extension to include files inline; a generation plugin; hand-maintained pages.
- Why: snippets would need markers inside the skill files or brittle line ranges to drop frontmatter. A plugin is another pinned dependency. A hook is standard MkDocs, testable as plain Python, and keeps the site at one dependency.
- Requirements affected: REQ-004-02, REQ-004-06

### Decision: Transcripts regenerated by fresh agent runs with a scripted newcomer
- Chosen: each Claude Code transcript comes from a fresh agent session on a scratch project, where the newcomer's answers to the skill's questions are supplied in advance and recorded. Devin CLI transcripts come from the owner's runs.
- Alternatives considered: reusing the trial conversation; writing transcripts by hand.
- Why: the trial conversation was not saved. Hand-written transcripts would be fiction. A fresh run with scripted answers is real agent output and repeatable.
- Requirements affected: REQ-004-04

### Decision: The example is committed without its git history
- Chosen: copy the trial's working tree into `examples/greenfield-go`, excluding the installed skills, and tell the commit history on a page.
- Alternatives considered: a submodule; a nested repository; replaying the commits.
- Why: a submodule adds a step for readers and nested repositories confuse tooling. The history matters as a story, not as objects.
- Requirements affected: REQ-004-08

### Decision: Strict build is the link checker
- Chosen: `mkdocs build --strict` in both workflows.
- Alternatives considered: a separate link checker action.
- Why: strict mode already fails on broken internal links and missing pages, which covers what matters for a small site, with no extra dependency.
- Requirements affected: REQ-004-01, REQ-004-13

### Decision: Reading time and spelling are tests, not reviews
- Chosen: a test counts words per authored page and scans for a short list of US spellings.
- Alternatives considered: reviewer judgement only.
- Why: the method's own rule is that what can be checked mechanically is. The lists are short constants with the requirement beside them.
- Requirements affected: REQ-004-09, REQ-004-10

## Interfaces and data

- `mkdocs.yml` at the repository root: `site_name`, `site_url`, `docs_dir: docs`, `strict: true`, theme features for tabs and code copy, Markdown extensions for admonitions, tabbed content and Mermaid fences, `hooks: [docs/_hooks/generate.py]`.
- `requirements-site.txt`: `mkdocs` and `mkdocs-material` pinned.
- `docs/_hooks/generate.py`: `on_files` adds generated pages `skills/<name>.md`, `templates.md`, `validator-rules.md`; pure functions `render_skill(text)`, `render_templates(dir)`, `render_rules(rules)` for the tests.
- `.github/workflows/pages.yml` and `.github/workflows/checks.yml`.
- `tests/test_site.py`.
- `examples/greenfield-go/`: the trial tree minus `.agents/`, `.claude/`, `.git/`.

## Risks

- GitHub Pages must be set to deploy from GitHub Actions in the repository settings. Mitigation: the owner has enabled it; the first deploy is a verification task.
- Material releases change configuration keys. Mitigation: exact pins, and the strict build fails loudly.
- Transcripts age as skills change. Mitigation: each shows its date and agent, and the skills pages are generated so the reference never ages.
